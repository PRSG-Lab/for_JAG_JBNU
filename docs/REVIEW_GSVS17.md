# GSVS17 패키지 검토 및 통합 제안

## 검토 범위

제공된 압축 파일에서 추출한 MATLAB 소스 7개와 README 1개를 정적으로 검토했다. 원본 파일은 수정하지 않았다. 압축 파일에는 원시 `.lvl` 자료나 과거 `.mat`·`.fig` 결과가 들어 있지 않다. 여기서 기록한 사항은 이 검토 시점의 소스 기준이며 MATLAB 실행 성공을 주장하지 않는다.

## 실행·의존성

- 계산에는 base MATLAB 함수(`fminsearch`, `optimset`, `gammainc`, `betainc`, `erfinv`, `randi`)를 사용한다. Statistics/Optimization Toolbox 전용 호출은 없다.
- 스크립트 내부 함수와 `dir(...).folder`가 있으므로 적어도 MATLAB R2016b 기능이 필요하다. `.fig`, `histogram` 등 MATLAB 그래픽과 `-v7.3` MAT 저장도 사용하므로 Octave 호환을 보증할 수 없다.
- 원본은 자료를 다운로드하지 않는다. `GSVS17_LVL` 폴더의 바로 아래 `.lvl` 파일을 두어야 한다. 기존 README의 출처는 NGS GSVS17 corrected levelling archive이다.
- `gsvs17_min_validation`을 먼저 실행하고 그 결과를 `gsvs17_addendum`이 읽는다. 두 스크립트 모두 현재 폴더 기준 경로를 사용하고 `clear; close all; clc;`를 실행하므로 단순 함수 래퍼의 지역 변수와 열려 있던 그림을 지울 수 있다.
- 최소 검증의 bootstrap 기본값은 2000회다. warm-start 외에도 시작점 은행의 첫 점을 계산하고 각 적합을 두 번 polish하므로 실제 소요시간을 작은 헬퍼 테스트로 추정할 수 없다.

## 통합 구조 제안

**최종 채택 방향:** 통합 담당자가 원본 ZIP을 provenance로 보존하고, active 모듈의 두 스크립트를 `RESULTS = gsvs17_min_validation(options)` 및 `ADD = gsvs17_addendum(options)` 함수로 전환하기로 했다. 어댑터는 `clear; close all; clc;`를 제거하고 데이터·출력·입력 MAT 경로만 주입한다. 기존 수치 코드·헬퍼·그림 설정·plot 블록은 보존한다. baseline/addendum 결과를 별도 폴더에 저장하고, 최종 모음에 addendum 1·3·4·6번과 baseline 2·5번을 복사한다. 아래 목록은 검토 당시 비교한 대안이며 이 최종 결정에 우선하지 않는다.

1. `modules/gsvs17/` 같은 독립 모듈로 원본 파일을 함께 보관하고, 다른 패키지와 수치 함수를 성급하게 합치지 않는다. 특히 기존의 백분위수 정의와 페어링 규칙은 논문 재현에 영향을 줄 수 있다.
2. 통합 진입점은 실행별 새 디렉터리를 만들고 원본 스크립트를 그 실행 디렉터리에 복사한다. 원본의 `pwd` 가정을 그대로 충족하는 `GSVS17_LVL/` 및 `results/` 구조를 준비한다. 스크립트 실행을 별도 내부 함수 프레임으로 격리하면 `clear`가 바깥 오케스트레이터 상태를 지우지 않는다.
3. MATLAB `run(fullpath)`는 대상 파일의 폴더로 이동할 수 있으므로, 파일을 모듈 원래 위치에 둔 채 임의 작업 디렉터리에서 `run`만 호출하는 방식은 피한다. 작업 디렉터리에 실행 사본을 만들거나, 경로만 주입하도록 매우 제한된 어댑터 변경을 명시한다.
4. main 완료 후 `results/`를 `calibration/` 등으로 복사하여 1–5번 원본 그림과 MAT를 보존한다. 이후 기존 설정 그대로 addendum을 실행해 수정된 1·3·4 및 6번 그림을 별도 보존한다. 두 버전이 섞인 최종 폴더를 유일한 결과로 남기지 않는다.
5. 기존 `close all` 동작으로 사용자 그림을 닫지 않도록 별도 MATLAB 프로세스 실행이 가장 강한 격리다. 단일 세션 래퍼라면 `clear`·`close all`·`clc`만 제거한 실행 사본을 쓰는 편의 어댑터를 명시하고, plot 블록은 그대로 유지할 수 있다.
6. 래퍼에서 경로·자료 존재·수치 옵션을 사전 점검하고 `onCleanup`으로 현재 폴더·MATLAB path·난수 상태를 복원한다. 원본 RNG 시드와 기본 bootstrap·격자는 바꾸지 않는다.
7. 원래 README는 provenance로 보존하되, 통합 README에는 현재 과학적 해석 범위를 별도로 적는다. 원본 문서의 심사 대응 지시문은 사용자 명령이 아니다.

## 그림 설정 보존 기준

분석 수치뿐 아니라 그림 블록·설정값·`apply_font_size.m`를 그대로 유지해야 한다. 새 통합 스타일 함수를 두 모듈 전체에 적용하지 않는다.

| 원본 | 고정 설정 |
|---|---|
| 두 스크립트 공통 | 글꼴 20 pt, `LW=2.0`, `MS=9`, PNG 300 dpi, `.fig` 저장, 흰 배경. 각 그림의 기존 축·범례·색상·마커·비율 설정 유지 |
| 최소 검증 그림 1·5 | 크기 900×700 pixel; 화면 위치는 각기 `[80 80]`, `[160 160]` |
| 최소 검증 그림 2·3·4 | 크기 1400×620 pixel; 화면 위치는 각기 `[100 100]`, `[120 120]`, `[140 140]` |
| addendum 그림 1·6 | 크기 980×760 pixel; 화면 위치는 각기 `[80 80]`, `[170 170]` |
| addendum 그림 3·4 | 크기 1450×640 pixel; 화면 위치는 각기 `[110 110]`, `[140 140]` |
| `apply_font_size` | 기존 축 라벨·제목 배율을 1로 만들고 모든 텍스트의 크기를 지정값으로 맞춤 |

최소 검증의 그림 블록은 `%% ... 8. FIGURES`부터 마지막 그림 저장·출력까지, addendum은 `%% ... 6. CORRECTED FIGURES`부터 마지막 그림 저장·출력까지이다. 통합 산출물과 원본의 이 구간을 문자열 또는 해시로 비교하면 코드 수준 보존을 확인할 수 있다. 같은 코드라도 MATLAB 버전·폰트·렌더러가 다르면 비트 단위 같은 PNG를 보장하지는 않는다.

## 발견 사항과 권장 처리

| 우선순위 | 위치 | 발견 사항 | 통합 시 처리 |
|---|---|---|---|
| 높음 | 두 실행 스크립트 첫 실행행 | `clear; close all; clc;`는 래퍼 지역 상태와 현재 세션 그림에 영향을 준다. | 실행 경계 격리 또는 실행 사본의 이 행만 제거. plot 설정 변경과 구별하여 기록. |
| 높음 | `gsvs17_addendum.m` 출력 경로 | 그림 1·3·4 이름이 앞 단계와 같다. | 단계별 결과 스냅샷·디렉터리 분리. |
| 높음 | 원본 README 및 일부 콘솔 해석 | 왕복차 적합으로 `tau_r`이 엄밀한 하한이라거나 논문의 경로 상한 `b_p`와 공동 공분산 집합이 검증되었다고 단정할 수 없다. | 새로운 README에서 section-pair diagnostic으로 한정. 원본 수치·그림은 보존. |
| 중간 | `fit_variance_ml.m:121–126` | `unpack`에서 자유모수에만 FLOOR를 더하지만 반환 직전 세 성분 모두에서 FLOOR를 뺀다. 고정 분산성분도 1e-12만큼 작아지고 `nll` 계산 분산과 반환 `v` 사이에 매우 작은 차이가 생긴다. | 재현성 때문에 이번 구조화에서 조용히 변경하지 말고 알려진 구현 특성으로 기록. 후속 수치 수정 시 별도 회귀 검증. |
| 중간 | `gsvs17_addendum.m:144–151` | `ID.vTot_*`와 `ID.bShare_*`는 bootstrap `sigma_s` 성분을 제외한다. 뒤의 그림 band는 `sigma_s`를 포함한다. | 'total variance'라는 저장 필드 설명을 전체 세 성분 합으로 단정하지 않는다. 기존 데이터에서 작을 수 있지만 일반 입력에서는 차이가 난다. |

| 중간 | `fit_variance_ml` 입력 | 길이 일치·양수 길이·유한 자료·비음수 고정값·양의 정수 시작 횟수 검사가 부족하다. | 통합 진입점 또는 검증 헬퍼에서 사전검사. 기존 적합식을 바꾸지 않는다. |
| 중간 | 파서의 B/S/E 처리 | 잘못된 S 행은 건너뛰고 부분 구간을 계속 누적한다. E 레코드와의 실제 일치 검사가 실행 코드에는 없다. 헤더 주석의 과거 검증을 매번 검증하는 것으로 설명하면 안 된다. | expected archive 사용 또는 새 데이터별 파싱 품질 확인. |
| 중간 | `build_fb_pairs` | 3회 이상 관측된 구간도 첫 관측·첫 역방향 한 쌍만 사용한다. 파일·구간 순서에 의존한다. | 페어링 규칙을 문서화. 다른 패키지의 쌍 구성 방식과 통일하지 않는다. |
| 낮음 | `build_fb_pairs` | 정렬된 SSN과 `desA/desB`의 방향 순서가 다를 수 있다. 두 dateStr가 모두 빈 값이면 sameDay=true가 된다. | SSN·`idxF/idxB`를 주요 식별값으로 사용. 새 자료에는 날짜 형식을 사전점검. |
| 낮음 | 프로파일 구간 | 신뢰구간은 지정 격자 범위의 점 단위 범위다. 끝점에 닿아도 절단 경고가 없다. | 경계값에 닿는 경우 격자 제한을 결과 해석에 표시. 기본 격자는 보존. |
| 낮음 | addendum subset | 충분한 표본 수 검사 없이 0.80 km까지 재적합한다. | 원본 GSVS17 자료를 전제로 하며 임의 소표본 입력에 대한 보장을 하지 않는다. |
| 낮음 | 통계 헬퍼 | 상관계수 함수는 상수·결측값을 처리하지 않고, `chi2inv`는 스칼라 자유도를 전제로 한다. | 입력 계약을 함수 카탈로그에 명시. |

## 과학적 해석과 보존의 구분

이번 요청은 패키지 구조화와 사용 설명이므로 위 구현 특성 때문에 과거 수치·그림을 임의로 바꾸지 않는 것이 적절하다. 최소 검증의 M0/M1 비교·부트스트랩은 모형 가정 아래 결과이며, 거듭제곱 함수도 정규·독립·평균 0 가정이 있는 모형이다. 동일일자 비교의 큰 p값은 등부하 공통 공분산 성분이 없다는 증명이 아니다. 구간별 상관, 평균구조, 대안 분산기작의 영향은 별도 검토가 필요하다.
